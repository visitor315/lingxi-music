## 二、任务背景与已完成工作

果果的原始诉求：音乐播放时歌词推进显示有问题。已完成的十一项核心修复与升级：

1. **采样驱动统一**（v2.6.7 已发布）：原生 250ms 定时器不再用未插值原始位置覆盖 currentSec；rAF 帧循环每帧单次采样贯穿进度条与歌词；JNI 调用从每帧 3-5 次降到 1-2 次；插值窗口 0.25s 改 0.5s。文件：src/js/03-audio-core.js（startNativeSyncTimer）、06-recommend.js（syncProgress 加 sampledSec 参数）、08-lyrics-ui.js。
2. **寻道落点修正**：点击歌词行/桌面歌词划动切句的寻道目标改为 `行时间 - LYRIC_AUDIO_OFFSET + 0.02`，填充从本句 0% 起唱点开始（原来是加偏移导致落点在句中 0.32 秒处）。
3. **拖进度条高亮滞留修复**：用 appliedActiveIdx（已应用到 DOM 的行号）做门控，替代直接比较 lastActiveIdx（拖动路径会绕过 DOM 应用）。
4. **普通 LRC 推进估算校准**：每字 0.30s 改 0.38s + 0.6s 基准，填充到估算人声终点即满格；超 7 秒间隔才判间奏定格。文件：04-lyrics-core.js parseLrc 末尾。
5. **偏移默认归零**：LYRIC_AUDIO_OFFSET 默认 0.00（原 0.15 提前导致直连输出下首字冒头），设置档位重排。
6. **QQ 音乐商业级 QRC 逐字歌词引擎接入**（核心突破，已集成至 05-search-api.js）：
   - 免签搜索 `client_search_cp` + 统一网关 `musicu.fcg`（PlayLyricInfo 模块获取十六进制 QRC）。
   - 纯 JS 实现的非标准 3DES（DES_BLOCK_SIZE=8，Key1/2/3 调度）解密，末尾去除填充 0 后通过原生 `DecompressionStream('deflate')` 解压，零外部依赖。
   - `convertQrcToKrcFormat` 将带真实毫秒绝对发声戳的 QRC 转换为播放器统一的词级时间轴。
   - 彻底解决首字冒头：QRC 带有乐句间真实的 260ms 到 500ms 伴奏/换气留白，首字未发声前填色百分比严格为 0%，杜绝酷狗 KRC 0ms 相邻行硬铺吃掉换气的问题。
7. **酷狗 KRC 词级逐字歌词引擎**（高可用备用逐字源）：
   - fetchKrcWordLyric(title, artist, durationSec)：酷狗搜索（mobilecdn.kugou.com api/v3）→ krcs.kugou.com 按 hash+duration 匹配 → download 接口拿 base64 → 跳过 4 字节 krc1 魔数 → 16 字节密钥循环异或 → zlib 解压。密钥：`40 47 61 77 5E 32 74 47 51 36 31 2D CE D2 6E 69`。
   - 当 QQ QRC 无结果或匹配失败时自动无缝无感替补。
8. **双源智能逐段锚点对齐 mergeKrcWithAnchorLyric**（05-search-api.js）：
   - 彻底修复上一版本行正则因 Windows `\r\n` 回车符导致 `line.match(/^\[(\d+),(\d+)\](.*)$/)` 全部返回 null 的 Bug。
   - **演职员假时间戳隔离**：严格过滤作词、作曲、编曲、混音等非演唱行，防止网易云把作曲打在 `00:01.00` 造成的巨幅插值畸变（解决如《不谓侠》首段抢跑 9 秒多）。
   - **前后半句拆分匹配**：支持 `startsWith` 前缀识别，解决酷狗/QQ将长句拆为两行卡拉OK而网易云合并为单行导致的匹配失败。
   - **智能母带与吸气声保护（解决呼吸声提前算歌词问题）**：
     - 若音频时长与 KRC/QRC 时长相符（3 秒内）且两源行差极差小于 2.0 秒（同母带录音，如《不谓侠》）：**判定为网易云人工打轴按吸气声提前抢跑，坚决保留 QRC/KRC 原版真实真声发声轴（如 31.08s 开唱），绝不向 30.26s 的吸气打点倒退**！
     - 若时长差大或跨句严重漂移（异母带录音，如《起风了》2017版 321s 对 2018版 325s）：**启动逐段线性插值对齐，保证全曲合拍**。
   - 缓存标记升级为 `[krc-anchor:5]`，TTL 升级为 `krc_attempt_ttl_v5`，自动静默刷新存量错误缓存。
9. **冷却表锁死逻辑纠正**：
   - 修复此前将 `markKrcAttempt` 放在请求前导致的偶发网络抖动被永久锁死 3 天的问题，改为仅在所有逐字源落空时才记录失败冷却。
10. **并发竞争消除与歌词排版稳定化**（05-search-api.js）：
    - 彻底删除 `selectSearchResult` 中并发触发的旧 `fetchLyricForSong` 冗余调用。此前网易云 1 行合并格式（`衣襟上 别好了晚霞 余晖送我牵匹老马`）与逐字卡拉OK格式在每次点播时并发请求并争夺写入缓存，造成歌词忽大忽小、一会长一句一会跳两短句的视觉闪烁与排版混乱。删除后由 `playSongAtQueue` 统一管理歌词生命周期，排版形态绝对确定稳定。
11. **浏览器输出延迟补偿**（03-audio-core.js measureAudioOutputLatency）：首次 playing 事件用 AudioContext.outputLatency 实测（0.01-0.3s 有效域）加进 LYRIC_AUDIO_OFFSET。仅浏览器环境，原生 MediaPlayer 路径不补偿。
12. **宣纸水墨过场动效与普通长句拦截门控**（03-audio-core.js, 06-player.css, 08-lyrics-ui.js）：
    - 采纳果果建议，彻底消除点播进入时屏幕闪现网易云单行长句（未换行合并行）的视觉跳动与排版闪烁。
    - 门控逻辑：仅当本地已存在完整的 `hasWordLyric` 且带 `[krc-anchor:5]` 的高质量商业/逐字词轴时才秒级上屏；若只有旧单行普通 LRC 或全新点播，坚决不上屏旧单行，而是进入优雅的宣纸水墨微光呼吸动效（`正在排版灵犀逐字词轴`），等 QRC / KRC 精准排版完成后平滑淡入；若双源均落空才在超时后平滑淡入普通文本保底。

当前所有已完成改动已在本地 git 提交安全固化（未推送远程，分支领先 origin/main 10 个提交）。

## 三、三级逐字歌词降级装载架构

```
点播曲目 (playSongAtQueue / loadBestAvailableLyric)
  │
  ├── 1. 检查是否存在最新本地歌词缓存 [krc-anchor:5]
  │     ├── 是 ──> 直接装载解析 (0ms 秒开)
  │     └── 否 ──> 触发后台多源装载链路
  │
  ├── 2. 第一优先：QQ 音乐商业级 QRC 歌词 (fetchQrcWordLyric)
  │     ├── 官方免签 client_search_cp 检索精确 songmid
  │     ├── musicu.fcg 获取十六进制 PlayLyricInfo
  │     ├── 纯 JS 3DES 私有分组解密 + 原生 DecompressionStream 解压
  │     └── 转换为标准逐字时间轴（带自然乐句呼吸停顿）
  │
  ├── 3. 第二优先（QRC 落空时）：酷狗 KRC 词级逐字歌词 (fetchKrcWordLyric)
  │     └── mobilecdn.kugou.com 检索 + krcs.kugou.com 异或解码
  │
  ├── 4. 智能母带判定与锚点插值 (mergeKrcWithAnchorLyric)
  │     ├── 同母带录音（如《不谓侠》）──> 100% 尊重真声音频起唱轴，保护换气空隙
  │     └── 异母带录音（如《起风了》）──> 逐段平滑插值对齐网易云音频
  │
  └── 5. 兜底保护（逐字全无）：网易云普通 LRC 原文 (fetchLyricForSong)
```
