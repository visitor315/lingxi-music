## 三、重大技术突破：QQ 音乐 QRC 商业级逐字歌词全链路打通

上一任 AI 遇到的核心卡点（搜索接口 500001 报需要签名）已被**彻底攻破并验证跑通**！

### 1. 突破点一：完全免签名的官方搜索接口
之前的 `musicu.fcg` 和 `client_search_cp` 均被腾讯新风控拦截，但腾讯官方的 Smartbox 联想搜索接口**零签名、零 Cookie、零防盗链限制、返回极速**：
- **请求地址**：`https://c.y.qq.com/splcloud/fcgi-bin/smartbox_new.fcg?key=${encodeURIComponent(query)}&format=json`
- **请求头**：`Referer: https://y.qq.com/`, `User-Agent: Mozilla/5.0`
- **返回结构**：`resp.data.song.itemlist[]` 直接包含：
  - `mid`: 歌曲唯一标识（即 `songMID`，例如起风了的 `0004jPDk2eB2dt`）
  - `name`: 歌名
  - `singer`: 歌手名
- **实测验证**：已在 `test-qrc-final.js` 中测试，100% 成功返回，无需任何 sign 计算。

### 2. 突破点二：免签名的 QRC 歌词获取
使用上一步拿到的 `songMID`，请求统一网关获取 QRC：
- **请求地址**：`https://u.y.qq.com/cgi-bin/musicu.fcg?data=${encodeURIComponent(payload)}`
- **负载内容**：
  ```json
  {
    "music.musichallSong.PlayLyricInfo": {
      "method": "GetPlayLyricInfo",
      "module": "music.musichallSong.PlayLyricInfo",
      "param": {
        "songMID": "0004jPDk2eB2dt",
        "qrc": 1,
        "crc": 1,
        "type": 1
      }
    }
  }
  ```
- **返回字段**：`resp['music.musichallSong.PlayLyricInfo'].data.lyric`
- **注意**：
  - `data.qrc` 只是一个整数标志位 1；
  - **真正的十六进制加密 QRC 数据存放于 `data.lyric` 中**（长度约 9600 字符）。

### 3. 突破点三：非标准 3DES 与解密算法实现
QQ 音乐 QRC 并非标准 3DES，而是结构类似 DES 的私有分组密码：
- **3 组 8 字节密钥**：
  - `KEY_1 = "!@#)(*$%"`
  - `KEY_2 = "123ZXC!@"`
  - `KEY_3 = "!@#)(NHL"`
- **解密调度流**：`D(KEY_3) -> E(KEY_2) -> D(KEY_1)`
- **S 盒特征**：使用腾讯私有的 8 个非标准 S 盒（SBOX1-SBOX8）与特殊位字节序映射（permuteFromKeyBytes）。
- **解压注意点**：解密出的二进制块末尾带有 3DES 的 0 填充字节（padding），直接传给浏览器标准的 `DecompressionStream('deflate')` 会报 `ERR_TRAILING_JUNK_AFTER_STREAM_END`；而微型解压库（如 `pako.inflate` 或 8KB 的 `fflate.unzlibSync`）能自动忽略尾部 padding 正常解压。建议在前端引入零依赖的微型 inflate（约几 KB）或在解压前截断。
- **验证样本**：已通过 `C:\Users\Administrator\Desktop\zcode-sandbox\test-qrc-final.js` 成功解密出 7873 字符的明文，写入 `C:\Users\Administrator\Desktop\zcode-sandbox\qifengle_decrypted.qrc`。

### 4. 突破点四：QRC 轴结构与首字冒头问题的根本性根治
实测解密出的 QRC 内容：
```text
[28887,2866]这(28887,483)一(29370,244)路(29615,504)上(30119,280)走(30399,375)走(30774,349)停(31123,378)停(31501,252)
[32021,2669]顺(32021,358)着(32379,316)少(32695,471)年(33166,349)漂(33515,276)流(33791,152)的(33943,172)痕(34114,299)迹(34413,276)
```
- **绝对发声时间**：每行括号内的字级时间 `(wordStartMs, wordDurMs)` 均为真实发声毫秒绝对戳。
- **真实换气停顿**：第一行在 31501 + 252 = 31753ms 结束，第二行在 32021ms 开始，**行间存在真实空隙（268ms 留白）**，首字发声点精准位于 32021ms，完全不存在酷狗 KRC 强制平铺占满行窗口导致的“人声未到、字先推进冒头”的问题！
- **转换为播放器内部结构**：
  - 行起始：`time = lineStartMs / 1000`
  - 词数组：
    `words = [{ text: "这", start: (wordStartMs - lineStartMs) / 1000, duration: wordDurMs / 1000 }, ...]`
  - 与当前 `parseLrc` 产出的 `LYRICS_DATA` 数据结构无缝契合！
