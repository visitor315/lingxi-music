## 二、任务背景与已完成工作

果果的原始诉求：音乐播放时歌词推进显示有问题。经五轮迭代，已完成：

1. **采样驱动统一**（v2.6.7 已发布）：原生 250ms 定时器不再用未插值原始位置覆盖 currentSec；rAF 帧循环每帧单次采样贯穿进度条与歌词；JNI 调用从每帧 3-5 次降到 1-2 次；插值窗口 0.25s 改 0.5s。文件：src/js/03-audio-core.js（startNativeSyncTimer）、06-recommend.js（syncProgress 加 sampledSec 参数）、08-lyrics-ui.js。
2. **寻道落点修正**：点击歌词行/桌面歌词划动切句的寻道目标改为 `行时间 - LYRIC_AUDIO_OFFSET + 0.02`，填充从本句 0% 起唱点开始（原来是加偏移导致落点在句中 0.32 秒处）。
3. **拖进度条高亮滞留修复**：用 appliedActiveIdx（已应用到 DOM 的行号）做门控，替代直接比较 lastActiveIdx（拖动路径会绕过 DOM 应用）。
4. **普通 LRC 推进估算校准**：每字 0.30s 改 0.38s + 0.6s 基准，填充到估算人声终点即满格；超 7 秒间隔才判间奏定格。文件：04-lyrics-core.js parseLrc 末尾。
5. **偏移默认归零**：LYRIC_AUDIO_OFFSET 默认 0.00（原 0.15 提前导致直连输出下首字冒头），设置档位重排。
6. **酷狗 KRC 词级逐字歌词引擎**（核心增量）：
   - fetchKrcWordLyric(title, artist, durationSec)：酷狗搜索（mobilecdn.kugou.com api/v3）→ krcs.kugou.com 按 hash+duration 匹配 → download 接口拿 base64 → 跳过 4 字节 krc1 魔数 → 16 字节密钥循环异或 → zlib 解压。密钥：`40 47 61 77 5E 32 74 47 51 36 31 2D CE D2 6E 69`。解码用浏览器自带 DecompressionStream('deflate')，零依赖。
   - parseLrc 支持 KRC 行格式 `[startMs,durMs]<off,dur,0>字`（04-lyrics-core.js），词标签正则支持可选第三字段；parseLrc 开头剥离 BOM。
   - 加载链：无缓存走 loadBestAvailableLyric（KRC 优先，失败回退 fetchLyricForSong 网易云链）；存量普通 LRC 缓存后台 upgradeLyricToWordLevel 升级。缓存写入带标记行 `[krc-anchor:2]`。
   - KRC 拉取冷却：localStorage 键 `krc_attempt_ttl_v2`，每曲 3 天。
7. **双源锚点对齐 mergeKrcWithAnchorLyric**（05-search-api.js）：酷狗母带与网易云音频前奏长度不同（起风了实测 KRC 比网易云晚约 1.318s），直接用会整段慢一句。算法：抓网易云普通 LRC 作锚点（fetchRawLrcFromNet 抽取的纯函数 + fetchAnchorRawLrc 支持按标题反查网易云 id），按归一化文本逐行匹配（含重复段落按出现次序对位），**取差值中位数做全局平移**（保留酷狗按发声打的轴心），匹配行不足 3 行退回逐行贴合。
8. **浏览器输出延迟补偿**（03-audio-core.js measureAudioOutputLatency）：首次 playing 事件用 AudioContext.outputLatency 实测（0.01-0.3s 有效域）加进 LYRIC_AUDIO_OFFSET。仅浏览器环境，原生 MediaPlayer 路径不补偿。
9. **杂项**：renderSongList 标题歌手补 escapeHtml（02-storage-and-cache.js）；删除死代码 startPlaybackLoop、applyLyricInterludeState 及 pending-next CSS；AGENTS.md 增加发布红线第 8 条。

## 三、当前未解决问题（正在攻坚）

**症状**：逐字歌词整体对齐已好，但个别句子首字填充早于人声冒头。果果的关键观察：首字唱得快的歌（如倾尽天下）正常；起风了这类抒情歌偶尔首字快。

**根因已实锤**：酷狗 KRC 的字级时间是按行窗口平铺的，不是实测发声点。实测起风了 KRC 全部 78 行首字偏移均为 0，行轴首尾相接（上一行词尾时间恰好等于下一行行头）。人声比节拍晚进的句子（换气、弱起），首字必然冒头。此信息 KRC 里不存在，无法调参解决。

**候选解法（按优先级）**：
1. **QQ 音乐 QRC 词级歌词**（推荐）：商业卡拉OK轴，字级时间带真实发声空隙。链路：QQ 搜索拿 songMID → `https://u.y.qq.com/cgi-bin/musicu.fcg` 模块 `music.musichallSong.PlayLyricInfo` 参数 `{songMID, qrc:1, crc:1, type:1}` 返回加密 qrc → 解密：hex 解码 → 3DES-ECB（Node 算法名 des-ede3-ecb，JS 端需自行实现或引小依赖）密钥 `!@#)(*$%123ZXC!@!` → zlib inflate → QRC 明文（行格式 `[startMs,durMs]字(startMs,durMs)字`，常带 XML 头需剥离）。**进度（避免重复踩坑）**：搜索接口两次尝试均失败——`c.y.qq.com/soso/fcgi-bin/client_search_cp` 返回 code 0 但 totalnum 恒 0（带不带 cookie 一样）；`u.y.qq.com/cgi-bin/musicu.fcg` 模块 `music.search.SearchCgiService`/`DoSearchForQQMusicDesktop` 返回 `code 500001`（需要 sign 签名，算法为公开的 zzc/zzb 前缀 base64-md5 变体，参考 LDDC 或 qqmusic-api 开源实现）。解密函数已写好未验证（qrc-probe.js / qrc-probe2.js）。**注意响应结构**：musicu.fcg 的返回数据在 `resp.music['music.musichallSong.PlayLyricInfo'].data`（模块名做键且挂在 music 字段下），不要按顶层取。搜索签名打通后整条链路预计一次跑通。CORS：QQ 接口大概率无跨域头，浏览器测试环境需走本地代理（见下），App 原生桥不受限。接入后作为词级首选源，KRC 退居第二，普通 LRC 兜底；锚点合并逻辑（中位数全局平移）原样复用。
2. 保守方案：KRC 首字晚起攻击（渲染层把每行首字填充起点延迟一小段并压缩后续），治标，仅当 QRC 路线确认走不通再考虑。

## 七、歌词系统架构速查

- 数据流：playSongAtQueue（03）→ 缓存/抓取（05）→ parseLrc（04）产出 LYRICS_DATA 数组项 `{time, text, singerTag, cleanText, words:[{text,start,duration}]}` → initLyricsList（08）渲染 → rAF 帧循环 tick（08 startLyricSmoothSync）每帧 `updateLyricProgressSmooth(-1, sampled)`：二分 findActiveLyricIndex 定行 → applyLyricLineChange 换行（含桌面歌词推送）→ 逐字分支按词级 start/duration 计算填充百分比 → CSS 渐变变量 --fill-pct。
- 时间基准：`curTime = 原生位置插值/currentTime + LYRIC_AUDIO_OFFSET`。设置项循环切换（08 cycleLyricOffsetSetting），档位 0.00 推荐/0.15/0.25/0.35/-0.15。
- 标记与缓存：yyrc_lyrics_cache（localStorage，键 title_artist 小写）；krc_attempt_ttl_v2 冷却；[krc-anchor:2] 行首标记表示已完成锚点对齐（换对齐算法时递增此版本号，旧缓存会自动重升级）。
- 已知取舍：KRC/QRC 音源与网易云播放流的母带差异用中位数全局平移吸收；匹配不上锚点的行保留原时间；QQ/QQ空间系接口在纯浏览器环境受 CORS 限制必须走本地 /krcp 代理（krcNetUrl 函数已做环境分流，接入 QRC 时把 host 加进 lingxi-dev-server.py 的 HOSTS 白名单与 krcNetUrl）。
